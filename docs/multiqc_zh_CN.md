# MultiQC 简体中文报告（zh_CN）

这个分支在英文流水线之上加了一层简体中文 MultiQC 报告。整层只由三个新文件组成
（本文档是分支上的第四个新增文件，仅作使用说明，不参与报告生成），
没有改动任何上游（nf-core/cutandrun）文件，也没有改 `nextflow.config`、工作流或
模块。不传激活配置时，报告与原版完全一致。

| 新文件 | 作用 |
|---|---|
| `assets/multiqc_config_zh_CN.yml` | 中文 MultiQC 配置。结构与 `assets/multiqc_config.yml` 一一对应，只翻译显示文本 |
| `conf/multiqc_zh_CN.config` | 激活配置。把 `params.multiqc_config` 指向上面的 zh 配置 |
| `assets/zh_CN/glossary.yml` | 术语表。每条被翻译的字符串逐字固定，并列出永不翻译的词 |

原理：MULTIQC 进程的命令行为 `multiqc -f [--config <params.multiqc_config>] .`
（`modules/local/multiqc.nf` L46-48：只有 `params.multiqc_config` 非空时才追加
`--config`）。上游 master 里 `assets/multiqc_config.yml` 只是作为进程输入被
stage 进来（`workflows/cutandrun.nf` L70/L922），并不写进命令行。因此：

- 不传激活配置 → 命令行为 `multiqc -f .`，报告与现有流水线行为完全一致；
- 传激活配置 → 命令行收到
  `--config $projectDir/assets/multiqc_config_zh_CN.yml`。

zh 配置是基础配置的完整拷贝（除 12 处翻译过的显示字符串和新增的 `title`
键外逐字相同），所以它给出的报告结构与上游预期一致：同样的 `run_modules`、
`custom_content` 与章节顺序。若将来基础配置也被传进命令行（上游改动或
用户 `-args`），MultiQC 按加载顺序让后加载的配置覆盖同名键，中文层依然
只替换翻译范围内的显示文本。

## 1. 如何启用

本地克隆（推荐）：

```bash
git clone https://github.com/Turing-Biotech/cutandrun.git
cd cutandrun
nextflow run . -profile docker -c conf/multiqc_zh_CN.config [其余参数照常用法]
```

直接按仓库名运行：

```bash
nextflow run Turing-Biotech/cutandrun -profile docker -c conf/multiqc_zh_CN.config [其余参数照常用法]
```

`[其余参数照常用法]` 指输入样本表、参考基因组等本流水线本来就需要的参数，
例如 `--input samplesheet.csv --genome mm10`。`-profile` 按计算环境换成
`singularity`、`conda` 等。

等价写法：也可以不传 `-c conf/multiqc_zh_CN.config`，直接传参数

```bash
nextflow run . -profile docker --multiqc_config assets/multiqc_config_zh_CN.yml
```

两种写法都只设置同一个 `params.multiqc_config`。同时传 `-c` 和
`--multiqc_config` 不冲突，值是同一个文件。

启用后在报告里确认三处：

1. 报告大标题（h1）为「CUT&RUN/CUT&TAG 质控报告（MultiQC 简体中文版）」。
2. 模块小节标题变中文，如「FastQC（过滤前）」「Bowtie2 比对（target 目标序列）」。
3. 报告末尾脚注为中文。

## 2. 什么被翻译，什么保持英文

### 翻译的（共 12 处显示值）

| 位置 | 英文原版 | 中文现值 |
|---|---|---|
| 报告标题（新增 `title` 键） | 无（默认用流水线名） | CUT&RUN/CUT&TAG 质控报告（MultiQC 简体中文版） |
| 报告脚注 `report_comment` | This report has been generated by ... | 本报告由 nf-core/cutandrun 分析流水线生成... |
| `module_order` 第 1 个 fastqc | FastQC (raw) | FastQC（过滤前） |
| `module_order` 第 3 个 fastqc | FastQC (trimmed) | FastQC（过滤后） |
| 上面两个 fastqc 的 `info` | This section of the report shows... | 本节展示接头去除（adapter trimming）前/后的 FastQC 质量结果。 |
| bowtie2 (target) | Bowtie2 (target) | Bowtie2 比对（target 目标序列） |
| bowtie2 (spike-in) | Bowtie2 (spike-in) | Bowtie2 比对（spike-in 内参序列） |
| samtools | Samtools alignment scores | Samtools 比对得分 |
| preseq | Library Complexity | 文库复杂度（Preseq） |
| picard | Picard duplication stats | Picard 重复率统计 |
| deeptools | Fragment QC | 片段长度质量（deeptools） |
| `section_comments` 一条 | CUT&TAG/RUN reads... (Per-base sequence content 批注) | 见 `assets/multiqc_config_zh_CN.yml` 中 `section_comments` 段 |

所有被翻译字符串的逐字值固定在 `assets/zh_CN/glossary.yml`，改词必须走术语表。

### 保持英文的，以及原因

- 全部键名、`run_modules`、`report_section_order`、`custom_content` 的键、
  `sp` 搜索模式、样本名清理规则（`extra_fn_clean_trim`）、段落锚点与绘图标识符。
  这些是代码和配置之间的接口，改一个字符就可能破坏流水线或将来无法跟上游合并。
- 自定义内容小节标题：peak counts、FRiP score、linear duplication、fragment
  lengths、software versions summary 等。它们的标题来自 `assets/multiqc/*.txt`
  表头文件和模块内部代码，翻译就必须改上游文件，违背本层不改动任何上游文件的
  原则，所以留英文。
- General Stats 大表的 MultiQC 自动列、表内数值。列组标签由 MultiQC 本身渲染。

## 3. 已知限制

- 导出的 PNG 图里可能出现 CJK 方块字（tofu）。General Stats 表导出的
  `multiqc_general_stats_table` PNG 由 matplotlib 生成，流水线容器里没有
  CJK 字体时，中文列组标签显示为方块。HTML 主报告在浏览器里正常显示。
  要给容器加中文字体属于容器改动，超出了本层的范围。

## 4. 本分支不做的事

- 不向上游 nf-core/cutandrun 发 PR。这个分支只对
  `Turing-Biotech/cutandrun`（fork）有效。
- README 保持原样，不加指向本文档的一行链接：README 是上游跟踪文件，
  改它会多出一个 `M`（modified）文件，破坏"diff 里只有新增文件"的零冲突
  合并保证。入口就是本文档（`docs/multiqc_zh_CN.md`）与激活配置
  `conf/multiqc_zh_CN.config` 文件名本身。
- 仓库所有权不需要手动转移：fork 直接建在 Turing-Biotech 组织下。
  （如果 fork 建在个人账号 artefaritaKuniklo 名下，需要用户手动在
  Settings > General > Transfer ownership 转到组织，本仓库已经建在组织下，
  没有这一步。）
- 不改容器镜像、字体、`nextflow.config` 或任何上游文件。

## English summary (for maintainers)

This branch adds a Simplified-Chinese MultiQC report as a purely additive
layer on this fork of nf-core/cutandrun. The report layer is three new files
(this document is a fourth, doc-only file), zero changes to upstream-tracked
files, so rebasing or merging upstream `master` later stays conflict-free:
`assets/multiqc_config_zh_CN.yml` is a full copy of
`assets/multiqc_config.yml` with 12 display strings translated (report title,
footer, module names and descriptions, one section comment);
`conf/multiqc_zh_CN.config` points `params.multiqc_config` at it, which the
pipeline already forwards to MultiQC as `--config`; `assets/zh_CN/glossary.yml`
pins every translated string and lists the never-translate terms. Run
`nextflow run . -profile <profile> -c conf/multiqc_zh_CN.config` to get the
Chinese report; without the flag the report is byte-for-byte the English
original. Section titles from custom content (peak counts, FRiP, linear
duplication, fragment lengths, software versions) and all config keys, search
patterns, sample-name trims and anchors stay English by design, because those
headings live in upstream-tracked header files and module code. One known
limitation: the exported General Stats PNG can show tofu for CJK labels when
the container lacks a CJK matplotlib font; the HTML report is unaffected.
No PR is opened against upstream nf-core/cutandrun. The README is also left
untouched on purpose: it is an upstream-tracked file, and a one-line pointer
there would add an `M` entry to `git diff --name-status upstream/master`,
breaking the all-`A` (added-only) merge guarantee — this document is the
pointer instead.
